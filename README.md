# 跑团角色卡档案馆

> DM 跑完团不再手动收卡——全团角色卡集中在一个网页里：卡片墙浏览、点开看详情、随时更新。
> 发一个链接，全团人随时翻看这部"设定集"。

作者：Percy ｜ vibe coding 课程 Day 1–7 的实践项目 ｜ PRD 见 `PRD.md`，技术方案见 `TECH_DESIGN.md`

## 现在能干什么

- **画廊墙**：打开就看到全部角色的卡片（缩略立绘 + 名字 + 职业/等级），按创建时间从新到旧排
- **详情页**：点任意卡片，看完整角色卡（身份标签 / 六属性 / 战斗数值 / 背景故事 / 立绘大图）和"最后更新时间"
- **添加 / 更新角色**（DM 专用）：填表保存即可；改已有角色时打开自动带出旧内容，保存即覆盖
- **立绘**：粘贴图片链接即可；不填就显示"暂无立绘"占位块
- **双链接机制**：浏览链接人人可看，管理链接带口令才能改（详见下文）

## 一张角色卡存什么（字段依据）

字段不是拍脑袋定的，是照着一张真实的 DND 5E 人物卡（NekoWorks DND 5E 人物卡 v4.4.0）定的：

| 分组 | 字段 |
|---|---|
| 基础 | 角色名、一句话简介、立绘链接 |
| 身份 | 玩家名、职业、等级、种族、阵营 |
| 六属性 | 力量、敏捷、体质、智力、感知、魅力 |
| 战斗数值 | 生命值 HP、护甲等级 AC |
| 叙事 | 背景故事、个性特点、理念、羁绊、缺陷、外貌描述 |

**调整值不存进数据库**：DND 规则里它等于 `⌊(属性数值 − 10) ÷ 2⌋`，是永远不会变的固定公式，
所以详情页现场算（力量 14 显示成「14 / +2」）。库里只存数值本身——少一个字段，也少一个填错的地方。

**本期不做的字段**（18 项技能、装备物品、法术位等）：PRD 定的 MVP 范围只到上面这些。
硬塞进来会让"添加一张卡"变成填 50 个格子，反而没人愿意用。

## 怎么在本地跑起来

前提：电脑上有 Python（Windows 可用微软商店版或 python.org 安装包）。

在本项目文件夹里打开终端，执行：

```bash
python -m http.server 8000
```

然后浏览器打开 <http://127.0.0.1:8000/index.html> 就能看到画廊。

> 为什么建议起这个服务：它让页面有个"正经的网址"，和上线后的样子一致。
> 直接双击 HTML 文件（file:// 方式）实测也能读到数据，但不推荐——
> 不同浏览器对本地文件的跨域限制不一样，换个环境不一定行。

## 两条链接怎么用（核心机制）

本项目**没有账号系统**（PRD 明确不做），用"两条不同的链接"区分身份：

| 链接 | 给谁用 | 长什么样 |
|---|---|---|
| **浏览链接** | 全团玩家，只读 | `index.html`，不带任何参数 |
| **管理链接** | DM 自己，可添加/更新 | `admin.html?key=口令` |

- 管理口令目前是：`2ce3wjnja75q`（生成后的初始值，建议改成你自己的）
- **改口令的位置**：`app.js` 顶部第 0 节，找 `var ADMIN_KEY = '...';` 换成你想要的字符串
- 想确认自己的完整管理链接：用管理链接打开管理页，页面下方会显示完整地址

### 已知边界（如实说明，不含糊）

1. **口令挡君子不挡技术高手**：网页代码在浏览器里跑，按 F12 就能看到口令。
   它防的是"误入"，不是"蓄意入侵"。真要安全得上账号系统（本期不做，见 PRD）。
2. **立绘走图片链接，不是上传文件**：原计划用云存储传文件，但云存储要求登录身份，
   与"零注册"冲突（Day 7 拍板 A+C 方案）。贴一个图片网址即可，效果相同。
3. **更新即覆盖，不留历史版本**：每张卡只有一份当前内容 + "最后更新时间"（PRD 红线第 4 条）。

```

```

## 技术栈（一句话版）

纯前端网页（HTML / CSS / JavaScript，无框架）+ WorkBuddy 云服务（云端数据库存角色卡）。
上线用 WorkBuddy 的"发布为应用"（Day 7 之后的事，见 PRD）。

## 关于密钥（给未来的自己）

`cloud-config.js` 里有一串 `wbpk_` 开头的字符。**它不是密码**——只是"这个应用"的身份证，
真正的门禁在云端服务端（校验请求来源）。所以它可以放在前端代码里。

但请注意：这个仓库目前是 Public，任何看到代码的人都能向这个数据库**读和写**。
MVP 阶段（数据是跑团角色卡，不是敏感信息）可以接受；
若之后存了不想公开的内容，把仓库转 Private 或换一个新的云端环境。
